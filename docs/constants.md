# Physical constants and reference values

Single source of truth: `include/constants.h` (`physics::constants`). Python reads the same
values from the `orbit` module (`orbit.G`, `orbit.C_LIGHT`, `orbit.AU`, `orbit.GM_SUN`,
`orbit.M_SUN`); do not hardcode them in scripts or notebooks.

| Constant | Value | Source |
|---|---|---|
| `G` | 6.67430e-11 m^3 kg^-1 s^-2 | CODATA 2018 |
| `C_LIGHT` | 299792458 m/s | SI definition (exact) |
| `AU` | 149597870700 m | IAU 2012 Resolution B2 (exact) |
| `GM_SUN` | 1.3271244004193938e20 m^3 s^-2 | JPL DE440 (`BODY10_GM` in `gm_de431.tpc`); IAU 2015 nominal is 1.3271244e20 |
| `M_SUN` | `GM_SUN / G` = 1.988409871326421e30 kg | derived so that `G * M_SUN` equals DE440 |

## System files

JSON files cannot include the header, so they carry copies of these values:

- Every `systems/*.json` that contains a Sun uses `mass = 1.988409871326421e30`, so `G * M_sun`
  matches DE440 (previously 1.98847e30, and 1.989e30 in `mercury.json`).
- `systems/earth_moon.json` places Earth at exactly 1 AU (149597870700 m) and the Moon 384,400 km beyond it.
- `systems/solar_system_spice.json` is generated by `python/spice_ic.py` with `mass = GM_DE440 / G` per body.
- Horizons-generated files take their Sun mass from the table in `src/io/horizons_builder.cpp`
  (now `physics::constants::M_SUN`); planetary masses in that table were not changed.

`tests/test_spice_constants.py` guards the SPICE file.

## Intentionally different

- Test fixtures in `tests/*.cpp` and `tests/test_helpers.h` use their own rounded values (Sun 1.98847e30, 1 AU = 1.496e11)
  as self-contained inputs; they do not read `systems/` and are not meant to match DE440.
- Planet masses other than the Sun in hand-built and Horizons files are rounded literature values (not GM/G).
